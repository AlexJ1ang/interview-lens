# 后端开发岗题库与出题方法论

## 一、出题方法论

按面试轮次定深度：
- **一面（基础）**：语言基础、数据库、网络、操作系统和常见故障分析——考概念是否准确、能否解释原因。
- **二面（深化）**：系统设计、高并发、中间件和工程取舍；若用户选择项目深挖模式，再以项目为主线考察。
- **三面（广度/主管）**：架构视野、跨栈理解、技术选型权衡、领导力。

按候选人回答动态调整：答得好就往下探一层，答得差就回退到基础知识定位真实水平。

## 二、高频考点清单

### 1. 语言与编程基础（按主流语言选配 Java/Go/Python/C++）
- Java：JVM 内存模型、GC 机制、HashMap/ConcurrentHashMap 原理、多线程与锁、线程池参数、synchronized 与 volatile、异常体系、反射与动态代理
- Go：goroutine 与 channel、GMP 调度模型、内存模型、defer/panic/recover、GC、slice 与 map 底层
- Python：GIL、装饰器、生成器、内存管理、多进程 vs 多线程、协程（asyncio）
- 通用：面向对象三大特性、设计模式（单例/工厂/观察者/策略）、SOLID 原则

### 2. 工程推理与代码理解
- 使用代码阅读、日志分析、接口设计、并发故障或性能定位场景考察解决问题能力。
- 可以讨论所用数据结构、复杂度和边界条件，但不要求现场写算法或手写代码。

### 3. 数据库（MySQL 为主）
- 索引：B+ 树原理、聚簇/非聚簇、最左前缀、索引失效场景、覆盖索引、回表
- 事务：ACID、隔离级别、MVCC、锁（行锁/间隙锁）、死锁
- 调优：慢查询分析、Explain 执行计划、分库分表、读写分离

### 4. 缓存与消息队列
- Redis：数据类型与底层结构、持久化（RDB/AOF）、缓存穿透/击穿/雪崩、分布式锁、淘汰策略、主从与哨兵/集群
- MQ（Kafka/RocketMQ/RabbitMQ）：削峰、解耦、消息丢失/重复/顺序、幂等、Kafka 分区与 offset

### 5. 网络与操作系统
- HTTP/HTTPS、TCP 三次握手四次挥手、TIME_WAIT、TCP vs UDP
- 进程/线程/协程、上下文切换、内存管理、线程安全

### 6. 系统设计与分布式（社招重点）
- 设计题：短链系统、秒杀系统、限流器、分布式 ID、IM 消息系统、排行榜
- 分布式：CAP、BASE、一致性（强/最终）、分布式事务、服务发现、负载均衡、熔断降级

## 三、示例题与答案要点

**例 1：以你使用的 JDK 版本为准，HashMap 为什么不适合并发写？怎么解决？**
答案要点：先确认 JDK 版本；并发写可能导致更新丢失、结构或计数状态不可预测。根据访问模式选择不可变数据、外部同步或 ConcurrentHashMap。追问时同样先限定版本，再讨论其并发控制和扩容机制，不把不同 JDK 实现混为一谈。

**例 2：哪些查询写法可能降低 MySQL 索引的可用性？你如何确认？**
答案要点：未满足联合索引前缀、对索引列施加函数或不匹配的类型转换、前导通配符，以及选择性过低等情况都可能影响访问路径；范围条件后的列能否继续参与定位或过滤取决于版本、索引结构和优化器。不能只背“索引失效”清单，应使用 EXPLAIN、实际数据分布和版本信息验证。

**例 3：缓存穿透/击穿/雪崩分别是什么、如何解决？**
答案要点：穿透→布隆过滤器/缓存空值；击穿→热点 key 互斥锁/逻辑过期；雪崩→缓存过期时间打散/多级缓存/熔断。追问：布隆过滤器的误判、互斥锁怎么做、逻辑过期 vs 互斥锁选择。

**例 4：设计一个短链系统。**
答案要点：编码（自增 ID + Base62 或哈希）、存储（KV 存储映射）、高并发读加缓存、唯一性（发号器/号段）、防冲突、过期时间。追问：哈希冲突怎么办、如何保证高性能、跳转用 301 还是 302。

**例 5：TCP 为什么是三次握手而不是两次？**
答案要点：防止历史失效连接请求到达服务端造成资源浪费、确认双方收发能力、同步初始序列号。追问：四次挥手为什么多一次（半关闭）、TIME_WAIT 作用与危害。

## 四、追问技巧

- 八股答对后，追问"为什么"和"不用它会怎样"（如"为什么不用红黑树做全部索引？"）。
- 给一个具体业务场景，让候选人现场设计/选型。
- 给出小段代码、日志或设计草图，让候选人解释风险、边界和改进方案；不要求现场手写算法。
- 报数据时追问口径："这个压测 QPS 是多少、什么机器配置、瓶颈在哪。"
